# Fresh workload trials favor QMD as an optional semantic route

A fresh GPT-6 test agent authored 30 fictional notes and 24 relevance questions without seeing the earlier engine outcomes: 20 positive questions have one active target, and four have no supported answer. The exact frozen suite hash is 57b03e775fcd7a930d41659d54f4f699e249f0b807d2eaad181c08be8372919c. All runs use isolated temp projections padded with repetitive fictional inventory notes; none reads the four live research projects. At 5000 units, first-place/top-five answers were lexical 11/20, SQLite FTS5 11/20, QMD vectors 20/20, zvec-grep 13/16 (out of 20 positive cases). Warm medians were 4.95 ms, 2.43 ms, 30.0 ms and 177 ms; fresh-process wall times with warm OS/model caches were about 97 ms, 56 ms, 1.44 s and 640 ms. Initial builds were 153 ms, 20 ms, 163 s and 6.79 s. These configurations use different models and runtimes; they do not isolate backend internals. Lexical already finds all answers within five, so fresh cases establish a ranking advantage for QMD, not additional fixed-union recall. The earlier public development union result remains 35/42 versus lexical 31/42.

The initial 500-unit run preserved a QMD worker failure: a minimal Node stdin probe reproduced blocked Bun child-process IPC in the sandbox and succeeded outside. The offline retry used explicitly staged dependencies, not a global installation. A separate fresh GPT-6 test audit found that same-ID post-edit retrieval did not prove content eviction, within-index rank stability did not imply repeatable builds, and report-end hashing could misattribute modified code. The strengthened 500-unit rerun directly checks SQLite/QMD current bodies, zvec stored entities and lexical body postings; replacement content excludes the old probe token, deleted units have no current indexed content, and all queried deleted IDs disappear. All four engines pass. Cold rankings match warm rankings and before/after suite, harness and model hashes show no changed inputs. The auditor verified the fixes read-only. Physical erasure of unreachable old vectors and post-mutation process restart remain outside these assertions. The 5000-unit run predates the stronger content checks. Old receipts and the original audit remain intact. Zvec first-result counts varied between fresh 500-unit builds (13-14), despite within-build stability; no seed-based reproducibility claim is made.

For the candidate, these measurements favor keeping dependency-free lexical retrieval as default and adopting the existing local QMD vector SDK as an explicit optional route. QMD offers the strongest tested semantic ranking and much lower repeated-query latency than the tested zvec route, but model startup and initial indexing should not burden every lookup. SQLite improves milliseconds without resolving the demonstrated semantic gap; default replacement would also require preserving different lexical semantics. RETRIEVAL.md defines the integration contract: canonical identity/status/provenance, exact-query preservation, offline explicit configuration, disposable projections, current-source binding and explicit fallback. No production backend has been integrated or installed. Broader live-project quality, interrupted/stale refresh integration, exact controls, archive history and packaging remain open.
