# Dogfood-and-mine: same-day fix loops, and agent-team ledger mining where workarounds are the unwritten spec

Digest of the dogfood-and-mine method, proven twice (first dogfood 2026-07-04 -> editio 0.3.0 same day; second 2026-07-06 -> the v0.4.0 worklist + doctor + numbers). THE LOOP: a real paper uses the tool -> the using session reports with REPRODUCTIONS (not impressions) -> fixes ship same-day while context is hot -> the release closes the loop and the version bump proves the cache key. THE MINE: when the feedback is not a report but a project's LEDGER, extract with an agent team — partition the ledger linearly across N readers (ours: 4 over 4023 lines) plus ONE cross-cutting retrieval agent driving kb-find/kb-get (which double-dogfoods promptus and surfaced kb-find's discoverability gap from its own experience); every extracted item carries evidence (timestamp + title + line) and a tag (explicit-ask / workaround / bug / convenience); workarounds are the richest vein — bespoke scripts a paper team wrote ARE the unwritten spec (Psi's emit/swap/reconcile scripts became editio-numbers' requirements verbatim). COSTS observed: ~5 Sonnet agents, ~700k tokens for a 522-unit ledger; the early-history slices returned nothing (research predating the tool) — date-window the partitions when the tool's adoption date is known. What this replaces: asking users what they want; the ledger already recorded what they DID.
