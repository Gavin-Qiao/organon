# Adversarial audit playbook: five lenses, refute-first, what-holds — and why the newest tool confesses

Digest of the 5-agent adversarial audit (2026-07-06/07), the method as much as the results. THE PLAYBOOK: five lenses, each a seam where docs can lie about code — (1) orchestrator surfaces vs scripts (every decision-table row and flag run for real), (2) the written authoring contract vs the renderer (construct attack inputs per documented row), (3) a dedicated FALSE-PASS hunt on the newest gate (make the tool lie, worst class first), (4) skills vs the data they describe (recompute every number; recompile the venue classes), (5) a cold-start journey following the docs literally from an empty repo. Discipline that made it work: every auditor must attempt to REFUTE its own finding before reporting, and must return a WHAT-HOLDS list so the audit is falsifiable; every behavioral fix then lands with a test replaying the auditor's exact attack. WHAT IT CAUGHT: all critical findings were in the tool built the SAME DAY (editio-numbers: --write laundering, unverified passing, unchecked tex content, unscanned escape hatch); the doubly-confirmed override no-op showed docs and the tool's own error message can both recommend a no-op; the renderer's silent classes (near-miss handles, typo'd grades, prose-as-math) were invisible precisely because nothing ever warned. WHAT HELD: mode-invariance byte-identical, venue widths to sub-0.01pt under real pdflatex, 10/10 citations verbatim — the disciplines that were already mechanized (golden contract, measured venues, verified references) survived attack. LESSON: adversarial audit belongs immediately after build, before release; age of code predicts finding density.
